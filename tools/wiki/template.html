Small start. Useful result.

Already installed? Use a local paradata file to create a report, or list questionnaires from a configured server.

GET STARTED

Install & connect

Check the local command first. Add a server connection when you need API access.

Load the matching package files

Use suso.ado, suso.sthlp, and suso.jar from the same build. In a fresh Stata session, change to the extracted project folder, then run:

adopath ++ "./install"
which suso
suso version
suso doctor, strict

The doctor check should pass and report backend 1.7.38-WINDOWSQA. Java 11 or newer must be available to Stata.

Install permanently or select the JAR

Replace the example path with your project’s location.

net install suso, from("C:/path/to/survey_solutions_api-main/install") replace

If automatic JAR discovery fails:

suso config, jar("C:/path/to/survey_solutions_api-main/install/suso.jar")
suso doctor, strict

Restart Stata after replacing a loaded JAR.

Choose local files or a server

Local paradata and reports work without API credentials. You can go straight to Paradata & reports.

For API work, enter the server URL, workspace short name, and API username supplied for your survey:

suso config, server("https://survey.example.invalid") ///
    workspace("primary") user("API_USER") auth(basic)
suso config, show

The example hostname will not connect. Settings are kept for the current Stata session.

Sign in and test the connection

For an interactive Basic-auth session, use the masked login prompt:

suso login
suso ping

login collects credentials. ping makes a server request to check access.

Batch runs, bearer tokens, and advanced settings

Batch runs need credentials supplied before requests. For Basic authentication, the command can read SUSO_PASSWORD from the environment. Bearer tokens require both auth(bearer) and token().

Keep literal secrets out of shared do-files and logs. Read the authentication reference for credential handling. Use the Configuration topic in the reference for timeouts, proxies, and questionnaire defaults.

How pagination works

Most REST lists return one page unless you add all. limit() caps total rows; pagesize() controls the requested page size. The session maxrows() cap still applies.

An explicit offset() or page() selects one page even with all. The meaning of offset() varies by action. Maps have separate pagination.

See defaults and page sizes.

Results, permissions, and server changes

return list shows available results. Copy values such as r(jobid) into local macros before the next command can overwrite them.

The server controls permissions and supported values. Actions such as assignment creation, interview approval, and deletion change server data. Check their required options in the reference before running them.

Options are action-specific: all, verbose, guid(), and replace are not universal switches.

GET YOUR DATA

Exports & backups

Download a new export, reuse an existing ZIP, or create a local archive run.

Online exports need a configured connection plus a questionnaire guid() and positive qver(). Downloads require verified HTTPS.
Online · Saves files

Download and extract in one command

Replace the questionnaire identity and paths. This starts a job, waits for it, downloads the ZIP, and extracts it.

suso export get, type(STATA) ///
    guid("11111111-2222-4333-8444-555555555555") qver(1) ///
    saving("C:/survey/survey.zip") ///
    unzipto("C:/survey/extracted")
return list
Start→Wait→Download→Extract

The data is saved to disk, not imported. Add replace to permit replacing the ZIP. Metadata is included by default.

Offline · Saves files

Extract a ZIP you already have

suso export extract, ///
    file("C:/survey/survey.zip") ///
    unzipto("C:/survey/extracted")

For an encrypted archive, add unzipw() or use the configured export password. Extraction can replace files in the destination; choose a fresh folder if needed.

Online · Saves an archive run

Back up a workspace

suso backup, ///
    dir("C:/survey/backups")

Creates a fresh run folder. Includes STATA exports by default. Review its manifest and failures; this is a selected archive, not a complete server image.

Long jobs, retries, and “NoFile”

pollsecs() defaults to 10 seconds; jobtimeout() defaults to 3,600 seconds. They govern preparation, separately from connection/read deadlines.

A timeout does not cancel the server job. Keep its JobId and inspect it before starting another export:

suso export status, id(12345) verbose
suso export download, id(12345) saving("C:/survey/recovered.zip")

Download only once the job has completed with a file. A successful get can instead return r(status)="NoFile"; no ZIP is created in that case.

Start manually and retain the job ID.

UNDERSTAND FIELDWORK

Paradata & reports

Start with full event history. Add questionnaire metadata and final data when your question needs them.

Save your work before loading paradata. Timing, flags, and reports can change the dataset in memory. Flags are signals for review, not proof of misconduct.
Needs: paradata.tab

Create a behaviour report

Get an offline HTML report covering interview timing and behaviour signals.

suso paradata load, file("C:/survey/paradata.tab")
suso paradata report, saving("C:/survey/behaviour.html") replace

Afterward: Stata contains the interview QC table. The report’s history viewer asks you to select the matching paradata file locally.

Needs: paradata + questionnaire HTML + main.dta

Build the combined QC suite

Explore Behaviour, Skips & removals, and Data QC in one HTML file.

suso paradata load, file("C:/survey/paradata.tab")
suso paradata suite, qx("C:/survey/questionnaire.html") ///
    data("C:/survey/main.dta") ///
    saving("C:/survey/qc_suite.html") replace

Afterward: the loaded events remain in Stata. Use the matching questionnaire preview HTML and one-row-per-interview main export.

Read the full question behind a variable

Add qx("C:/survey/questionnaire.html") to report or suite. Hover over or keyboard-focus variable names to read their questionnaire text, including in event history. Regenerate older reports to add this feature.

Investigate pauses and interview time changes

Use startvar(your_start_field) endvar(your_end_field) on report or suite to select the pair for your questionnaire. Supply both together; they override automatic detection.

The review queue explicitly flags in-survey pauses, an end time before its corresponding start, and substantial revisions to interview start/end captures. Open the interview to see the actor and evidence.

Normal completion pauses, identical captures, and small adjustments are excluded. These are follow-up prompts; they do not establish intent.

Choose a focused check

Calculate interview flags
suso paradata load, file("C:/survey/paradata.tab")
suso paradata flags, gapmins(30) fastsecs(2) ///
    saving("C:/survey/flags.dta") replace

Leaves one row per interview with six flags and n_flags. Changing timing thresholds later requires reloading the original events.

Read timing and flag definitions.

Summarize question timing
suso paradata load, file("C:/survey/paradata.tab")
suso paradata timing, by(question) vars("employment* sales*")
save "C:/survey/question_timing.dta", replace

Substitute your question patterns. Leaves a question-level timing table. These are answer-gap measures, not total time spent on a question.

Review removed answers
suso paradata load, file("C:/survey/paradata.tab")
suso paradata skips, qx("C:/survey/questionnaire.html") ///
    data("C:/survey/main.dta") cascade(3) window(60) ///
    saving("C:/survey/removals.dta") ///
    html("C:/survey/removals.html") replace

Leaves an interview-level removal summary. A historical removal does not mean the final answer is blank.

Audit final data without loading paradata
suso paradata check, qx("C:/survey/questionnaire.html") ///
    data("C:/survey/main.dta") ///
    saving("C:/survey/question_checks.dta") ///
    html("C:/survey/data_qc.html") replace

Leaves one audit row per codebook question. Unsupported questionnaire logic remains unevaluated. If you specify misscodes(), it replaces the default missing-code list.

Understand filters and the three report views
  • Behaviour: timing and actions in the event history.
  • Skips & removals: historical answer removals and their final-data context.
  • Data QC: final answers compared with questionnaire metadata.

In a suite, command if and status() filters restrict Data QC only. The report views have different populations; their counts need not match.

GET UNSTUCK

Troubleshooting

Start with the message Stata prints. Choose the symptom below for the next check.

Stata cannot find suso, or the backend does not match
which suso
suso version
suso doctor, strict

Check that the ADO and JAR come from the same build. Reinstall matching files and restart Stata after replacing the JAR. A different copy may be earlier on the adopath.

Review installation steps →
Authentication or connection fails
suso config, show
suso ping, verbose

Check the server, workspace, authentication mode, and account permissions. A 401/403 response concerns the API account; 407 concerns proxy authentication. A successful doctor check only verifies the local runtime.

For TLS errors, check the certificate hostname and Java trust store. Downloads require verified TLS; insecure is not a download workaround.

The list is shorter than expected

Add all where supported. Check limit(), configured maxrows(), filters, and any explicit page/offset. A successful list can still stop at a configured cap.

Review pagination rules →

ErrorWhat to check

601Input filename, extension, working directory, or JAR location.
602Use a new output name, or replace if that action supports it and replacement is intended.
459Read the preceding diagnostic; it may concern API validation, cached analysis, or the runtime.

Quote paths with spaces. Use pwd to check Stata’s working directory. Use guid() for an API questionnaire and qx() for local preview HTML.

An export times out or produces no ZIP

The server may still be preparing the job. Keep the JobId and use export status before starting again. NoFile can be a valid completed outcome for the requested filters.

Review export recovery →
Report counts or flags look unexpected

Reload the full original event file before changing timing thresholds or role scope. Check actor, status, and question filters. Historical removals, event behaviour, and final-data QC answer different questions.

Use the matching questionnaire preview and main export. An unevaluated rule is not a passed check.

Open detailed analysis troubleshooting →
When reporting a problem, include the exact command, full error, suso version, and suso doctor output. Remove passwords, tokens, and survey records.
